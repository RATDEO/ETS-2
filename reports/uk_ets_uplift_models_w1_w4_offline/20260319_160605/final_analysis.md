# Final Analysis

This benchmark tested stronger learned uplift policies under a conservative exact offline constraint.

Models tested:
- `uplift_logistic`
- `uplift_gbdt`

Method:
- windows processed causally in order `W4 -> W3 -> W2 -> W1`
- training pool for each target window:
  - all prior windows' validation and test rows
  - the current window's validation rows
- thresholds selected on a chronological holdout inside that pool
- test predictions generated by keeping only those baseline `gate_top20` applications that the uplift model still endorsed

Main result:
- baseline `gate_top20` mean `W1-W4` path MSE: `54.613995`
- `uplift_gbdt`: `54.716716`
- `uplift_logistic`: `54.742025`

So both stronger uplift models were worse than the current `top20` gate.

Interpretation:
- The uplift models did reduce apply rates sharply:
  - `uplift_gbdt` mean apply rate: `6.56%`
  - `uplift_logistic` mean apply rate: `7.97%`
- That did trim some damage in `W4`, but it also removed too much of the already small useful signal elsewhere.
- `uplift_gbdt` was better than `uplift_logistic`, but not enough to beat baseline.

What this means:
- Moving from threshold heuristics to a better-formulated uplift classifier was directionally sensible, but it still did not solve `W1-W4`.
- The current hard-window problem is not just “wrong threshold” or “wrong classifier form”.
- The likely remaining bottlenecks are:
  - weak or unstable memory evidence in the hard regimes
  - insufficient regime representation in the training data
  - the conservative offline setup only allowing suppression, not new applications

Practical next step:
- If we keep working this line, the next experiment should be a full live rerun where the uplift model is allowed to both add and remove applications, not just suppress existing ones.
- If we want the highest expected payoff, the next broader move is probably improving memory quality / regime representation rather than just swapping classifiers again.
