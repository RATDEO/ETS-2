1. The EU ETS & Carbon Markets

What is the EU ETS?

The European Union Emissions Trading System (EU ETS) is the world's largest carbon market. Think of it as a system where companies must buy permits (called European Union Allowances — EUAs) for each tonne of CO₂ they emit. Fewer permits are issued each year, so the price rises, incentivising companies to cut emissions.

💡 Real-World Analogy

Imagine a school with 100 "noise permits". Each permit lets you shout once in the corridor. If you run out, you must buy more from someone else. As the school reduces total permits each term, the price of shouting goes up — so students learn to be quieter.

Why Forecast EUA Prices?

EUA prices drive investment decisions worth billions. If a power company can predict that carbon prices will rise from €65 to €80 over the next month, they might switch to natural gas (lower emissions) earlier. Our repo builds models that forecast the EUA futures price 30 trading days ahead.

2. Time Series Fundamentals

What Is a Time Series?

A time series is a sequence of data points ordered by time. The EUA closing price each day forms a time series:

y₁, y₂, y₃, …, yₜ where yₜ = price on day t

Key Concepts

Returns (Log Returns)

Instead of working with raw prices, we often use log returns. These are more statistically well-behaved (closer to normally distributed):

rₜ = ln(yₜ / yₜ₋₁) = ln(yₜ) − ln(yₜ₋₁)

To convert back from returns to prices, we use the inverse:

yₜ₊ₕ = yₜ · exp(rₜ₊₁ + rₜ₊₂ + … + rₜ₊ₕ) = yₜ · exp(Σᵢ₌₁ʰ rₜ₊ᵢ)

Here's how the code does it:

def returns_to_prices(returns: np.ndarray, last_price: float) -> np.ndarray:
    """Convert log returns to price path."""
    last_price = float(last_price)
    return last_price * np.exp(np.cumsum(returns, axis=0))

🔑 Why cumsum?

np.cumsum computes the running total: [r₁, r₁+r₂, r₁+r₂+r₃, …]. When we exp() that and multiply by the last known price, we get the full predicted price path. This is because ln is the inverse of exp.

Volatility

Volatility measures how much prices fluctuate. We typically use the standard deviation of log returns over a rolling window:

σ₂₀ = std(rₜ₋₁₉, rₜ₋₁₈, …, rₜ)

Higher σ means more uncertainty. The repo uses a 20-day window by default.

Trend and Momentum

Trend = the general direction of prices (up or down). Momentum = the speed of change. In the code:

# 5-day momentum
momentum_5d = y[-1] - y[-5]

# 5-day percentage change
pct_change_5d = (y[-1] / y[-5] - 1) * 100

Stationarity

A time series is stationary if its statistical properties (mean, variance) don't change over time. Raw prices are not stationary (they trend up/down), but log returns usually are. Many models (like ARIMA) require stationarity, which is why differencing (computing returns) is so common.

Autocorrelation

Autocorrelation measures how much today's value is correlated with yesterday's, or the day before that, etc. If today's price is highly correlated with yesterday's, the series has strong autocorrelation at lag 1. The Autoformer model in this repo explicitly uses autocorrelation patterns.

4. Sliding Windows & Train/Val/Test Splits

The Sliding Window Approach

To train a model, we need input→output pairs. We create them by sliding a window across the time series:

Day: 1 2 3 ··· 120 121 122 ··· 150 ├───── seq_len = 120 ─────┤├── pred_len = 30 ──┤ │ INPUT (X_enc) ││ TARGET (y) │

We slide this window one day at a time to create thousands of training examples:

@dataclass
class WindowConfig:
    seq_len: int = 120   # Input: look at 120 past days
    label_len: int = 30  # Decoder context overlap
    pred_len: int = 30   # Output: predict 30 future days

Array Shapes (Critical!)

ArrayShapeMeaning
X_enc(N, 120, F)N windows × 120 days × F features
X_dec(N, 60, F)Decoder input (30 label + 30 prediction)
y(N, 30)The 30 target prices we want to predict
dates(N,)The first prediction date for each window

Train/Validation/Test Split

Unlike random splits in classification, time series must be split chronologically to avoid data leakage (using future data to predict the past).

←──── Train ────→←─ Val ─→←── Test ──→ 2017-01-01 2023-06-30 2024-06-30 2026-01-05 
def split_windows(X_enc, X_dec, y, dates, train_end, val_end):
    train_end = pd.Timestamp(train_end)
    val_end = pd.Timestamp(val_end)
    dates = pd.to_datetime(dates)
    
    train_mask = dates <= train_end
    val_mask   = (dates > train_end) & (dates <= val_end)
    test_mask  = dates > val_end
    
    return {
        "train": {"X_enc": X_enc[train_mask], ...},
        "val":   {"X_enc": X_enc[val_mask], ...},
        "test":  {"X_enc": X_enc[test_mask], ...},
    }

🎯 Key Idea: No Future Leakage

The model is trained on data up to June 2023, validated on Jul 2023–Jun 2024, and tested on Jul 2024–Jan 2026. At no point does training data contain information from the future test period. This is essential for honest performance evaluation.

5. Baseline Models

Before building complex models, we need simple baselines to compare against. If a fancy model can't beat a naive baseline, it's not useful.

Naive Persistence

The simplest possible forecast: tomorrow's price will be today's price (for all 30 days).

ŷₜ₊ₕ = yₜ for all h = 1, 2, …, 30
class NaivePersistence(BaseForecaster):
    def predict(self, y):
        if y.ndim == 1:
            y = y.reshape(1, -1)
        last_value = y[:, -1:]          # Shape: (batch, 1)
        predictions = np.repeat(last_value, self.pred_len, axis=1)
        return predictions             # Shape: (batch, 30)

💡 Why is this useful?

In efficient markets, prices follow a random walk, meaning the best prediction of tomorrow's price is today's price. If our model can't beat this, our model isn't capturing any signal.

Seasonal Naive

Uses weekly patterns: next Monday will be like last Monday. With 5-day trading weeks:

ŷₜ₊ₕ = yₜ₊ₕ₋₅ (repeat the pattern from one week ago)

Linear Regression Baseline

A separate Ridge regression model for each horizon, using hand-crafted features:

def _create_features(self, y):
    features = []
    for lag in [1, 5, 10, 20]:
        features.append(y[:, -lag])          # Lagged values
    features.append(np.mean(y[:, -20:], axis=1))  # 20-day mean
    features.append(np.std(y[:, -20:], axis=1))   # 20-day std
    features.append(y[:, -1] - y[:, -5])        # 5-day momentum
    return np.column_stack(features)

Ridge regression minimises:

L = Σᵢ(yᵢ − ŷᵢ)² + α · Σⱼ wⱼ²

where α is the regularisation strength. The penalty term α · Σ wⱼ² prevents weights from growing too large (overfitting).

ARIMA

ARIMA(p, d, q) = AutoRegressive Integrated Moving Average. A classic statistical model:

  • AR(p): Use the last p values as inputs (autoregressive)
  • I(d): Difference the series d times to make it stationary
  • MA(q): Use the last q forecast errors

The repo uses ARIMA(5, 1, 2) by default:

model = ARIMA(y, order=(5, 1, 2))
fitted = model.fit(disp=False)
forecast = fitted.forecast(steps=30)

6. DLinear: Decomposition + Linear Mapping

The Big Idea

A 2022 paper asked: "Are Transformers Effective for Time Series Forecasting?" They showed that a simple linear model often beats complex transformers. DLinear works by:

  1. Decompose the input into trend and seasonal components
  2. Apply a separate linear layer to each component
  3. Add them back together
Input (120 days, F features) │ ┌────┴────┐ │ AvgPool │ ← Moving average (kernel_size=25) └────┬────┘ │ ┌────┴────────────┐ │ │ Trend Seasonal (smooth) (input − trend) │ │ Linear(120→30) Linear(120→30) │ │ └────────┬────────┘ │ Output (30 days) Trend + Seasonal

Code Walkthrough

class DLinear(nn.Module):
    def __init__(self, seq_len, pred_len, enc_in, individual=True, kernel_size=25):
        super().__init__()
        # Moving average for trend extraction
        padding = (kernel_size - 1) // 2
        self.avg = nn.AvgPool1d(kernel_size=kernel_size, stride=1, padding=padding)
        
        if individual:
            # Separate linear layer per feature channel
            self.Linear_Trend = nn.ModuleList([
                nn.Linear(seq_len, pred_len) for _ in range(enc_in)
            ])
            self.Linear_Seasonal = nn.ModuleList([
                nn.Linear(seq_len, pred_len) for _ in range(enc_in)
            ])

    def forward(self, x_enc, x_dec=None):
        # Step 1: Decompose into trend + seasonal
        x = x_enc.permute(0, 2, 1)    # (batch, features, seq_len)
        trend = self.avg(x).permute(0, 2, 1)
        seasonal = x_enc - trend
        
        # Step 2: Apply separate linear maps
        for i in range(self.channels):
            trend_out[:, :, i] = self.Linear_Trend[i](trend[:, :, i])
            seasonal_out[:, :, i] = self.Linear_Seasonal[i](seasonal[:, :, i])
        
        # Step 3: Recombine
        output = trend_out + seasonal_out
        return output[:, :, :1]  # Return only target channel

Why It Works

The decomposition separates "where prices are heading" (trend) from "short-term oscillations" (seasonal). A linear layer nn.Linear(120, 30) is just a matrix multiplication:

output = W · input + b where W is a 30×120 matrix

Each output day is a weighted sum of all 120 input days. The model learns which past days matter most for each future day.

🧮 A-Level Maths Connection: Matrix Multiplication

If you have a column vector x of length 120 (past prices) and a matrix W of size 30×120, then Wx gives a vector of length 30 (future prices). Each element of the output is a dot product of one row of W with the input — that's just a weighted average where the model learns the weights.

7. Autoformer Architecture

What Is a Transformer?

Transformers (from the 2017 "Attention Is All You Need" paper) use attention to decide which parts of the input are most relevant. Instead of processing input sequentially (like ARIMA), transformers look at all positions simultaneously.

The Attention Formula

Attention(Q, K, V) = softmax(QKᵀ / √d) · V

Where:

  • Q (Query) = "What am I looking for?"
  • K (Key) = "What do I contain?"
  • V (Value) = "What's my actual content?"
  • d = dimension of the keys (for numerical stability)

The softmax converts scores into probabilities (weights that sum to 1), then we take a weighted average of the values.

Auto-Correlation Mechanism

The Autoformer replaces standard attention with auto-correlation. Instead of learning arbitrary attention patterns, it finds the natural periodic patterns in the data:

class AutoCorrelation(nn.Module):
    def forward(self, queries, keys, values):
        B, L, _ = queries.shape
        H = self.n_heads
        
        # Project into multi-head space
        queries = self.query_projection(queries).view(B, L, H, -1)
        keys = self.key_projection(keys).view(B, S, H, -1)
        values = self.value_projection(values).view(B, S, H, -1)
        
        # Compute attention scores
        scale = 1. / np.sqrt(self.d_keys)
        scores = torch.einsum("blhe,bshe->bhls", queries, keys) * scale
        
        # Softmax → probabilities
        attn = F.softmax(scores, dim=-1)
        
        # Weighted sum of values
        out = torch.einsum("bhls,bshd->blhd", attn, values)
        return self.out_projection(out.reshape(B, L, -1))

Multi-Head Attention

Instead of one attention computation, we split into 8 heads (by default), each focusing on different patterns. With d_model=512 and 8 heads, each head works with 512/8=64 dimensions.

Series Decomposition Blocks

Between every attention layer, the Autoformer decomposes the signal:

class SeriesDecomp(nn.Module):
    def forward(self, x):
        trend = self.moving_avg(x)  # Smooth the signal
        seasonal = x - trend       # What's left = oscillations
        return seasonal, trend

Encoder-Decoder Architecture

Encoder (processes input): ┌──────────────────────────────────────────┐ │ Input Embedding → Linear(F → 512) │ │ ↓ │ │ EncoderLayer × 2: │ │ AutoCorrelation → Decomp → FFN → Decomp│ └──────────────────────┬───────────────────┘ ↓ Decoder (generates output): ┌──────────────────────────────────────────┐ │ Decoder Embedding → Linear(F → 512) │ │ ↓ │ │ DecoderLayer × 1: │ │ Self-Attention → Decomp → FFN → Decomp │ └──────────────────────┬───────────────────┘ ↓ Projection: Linear(512 → 1) → 30 price predictions

Residual Wrapper

The repo adds an optional residual connection to naive persistence:

class ResidualWrapper(nn.Module):
    def forward(self, x_enc, x_dec):
        # Naive prediction: repeat last known value
        naive_pred = x_enc[:, -1:, 0:1].expand(-1, self.pred_len, -1)
        
        # Model predicts a residual (correction)
        residual = self.base_model(x_enc, x_dec)
        
        # Blend: start close to naive, let model gradually contribute
        blend = torch.sigmoid(self.alpha)  # Learnable weight in [0, 1]
        return naive_pred + blend * residual

💡 Why Add a Residual Connection?

This ensures the model at worst matches the naive baseline. The model only needs to learn the correction to persistence, not the entire price level. This is much easier to learn.

8. Training Deep Models (PyTorch)

The Training Loop

Training a neural network is an iterative process of: predict → measure error → adjust weights.

# Core training loop (simplified from src/models/tsm.py)
criterion = nn.MSELoss()           # Loss function
optimizer = torch.optim.AdamW(     # Weight updater
    model.parameters(), lr=0.0001, weight_decay=0.0
)

for epoch in range(100):
    for batch in train_loader:
        # 1. Forward pass: make predictions
        output = model(batch["X_enc"], batch["X_dec"])
        
        # 2. Compute loss: how wrong are we?
        loss = criterion(output, batch["y"])
        
        # 3. Backward pass: compute gradients
        loss.backward()
        
        # 4. Gradient clipping: prevent explosions
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        
        # 5. Update weights
        optimizer.step()
        optimizer.zero_grad()

Key Concepts

Loss Function: MSE

MSE = (1/n) · Σᵢ (yᵢ − ŷᵢ)²

Squares the errors so large mistakes are penalised much more than small ones.

Gradient Descent

Imagine you're on a hill in fog and want to reach the lowest point. You feel the slope at your feet (the gradient) and take a small step downhill. Repeat until you can't go lower.

wₙₑₓₜ = w − η · ∂L/∂w

where η = learning rate (step size) = 0.0001 in this repo.

AdamW Optimizer

AdamW is an advanced gradient descent method that:

  • Adapts the learning rate per parameter (frequently updated params get smaller steps)
  • Uses momentum (keeps moving in recent direction, like a ball rolling)
  • Applies weight decay separately from gradient (proper L2 regularisation)

Early Stopping

We track validation loss each epoch. If it hasn't improved for patience=10 epochs, we stop training and use the best checkpoint.

if val_loss < self.best_val_loss:
    self.best_val_loss = val_loss
    no_improve = 0
    self.save(save_path)     # Save best model
else:
    no_improve += 1
    if no_improve >= patience:
        break               # Stop early!

Cosine Annealing Learning Rate

The learning rate isn't constant — it follows a cosine curve, starting high and gradually decreasing:

η(t) = η_min + ½(η_max − η_min)(1 + cos(πt/T))

This helps the model explore broadly early on, then fine-tune as it converges.

9. Evaluation Metrics

Why Multiple Metrics?

No single metric captures everything. We use several:

MetricFormulaWhat It Measures
MSE(1/n) Σ(y−ŷ)²Average squared error — penalises big mistakes heavily
RMSE√MSESame units as the data (EUR) — more interpretable
MAE(1/n) Σ|y−ŷ|Average absolute error — treats all errors equally
MAPE(1/n) Σ|y−ŷ|/|y| × 100Percentage error — scale-independent

Code Implementation

def mse(y_true, y_pred):
    return np.mean((y_true - y_pred) ** 2)

def rmse(y_true, y_pred):
    return np.sqrt(mse(y_true, y_pred))

def mae(y_true, y_pred):
    return np.mean(np.abs(y_true - y_pred))

def mape(y_true, y_pred, epsilon=1e-8):
    return np.mean(np.abs((y_true - y_pred) / (np.abs(y_true) + epsilon))) * 100

Horizon-Specific vs. Path-Level Evaluation

Horizon-Specific

Evaluate at specific forecast horizons: Day 1, Day 5, Day 20, Day 30. This tells us "how accurate is the model N days ahead?"

# For horizon h=5 (1-indexed):
y_true_h5 = y_true[:, 4]   # 0-indexed → column 4
y_pred_h5 = y_pred[:, 4]
mse_h5 = np.mean((y_true_h5 - y_pred_h5) ** 2)

Path-Level (Paper-Style)

Average MSE across all 30 steps. This matches the carbon price paper's evaluation:

MSE_path = (1/(n·30)) · Σₜ Σₕ (y_true[t,h] − y_pred[t,h])²
def compute_path_metrics(y_true, y_pred):
    # Flatten all predictions → single MSE
    global_metrics = compute_global_metrics(y_true, y_pred)
    return {f"{name}_path": value for name, value in global_metrics.items()}

10. Trend Classification

Going Beyond Numbers: Did the Model Get the Direction Right?

Even if the exact price forecast is off, getting the direction right (up/down/flat) matters for trading decisions.

Our Approach (Volatility-Based Threshold)

threshold = 0.25 × σ₂₀ × mean(recent prices)
  • If price change > threshold → UP (+1)
  • If price change < −threshold → DOWN (−1)
  • Otherwise → FLAT (0)

Paper-Style (α-Band around Historical Mean)

The carbon paper uses a 2% neutrality band around the mean of the last 18 prices:

ref = mean(yₜ₋₁₇, …, yₜ) UP: yₜ₊ₕ > (1 + 0.02) × ref DOWN: yₜ₊ₕ < (1 − 0.02) × ref FLAT: otherwise 
def compute_paper_trend_accuracy(history, y_true, y_pred,
                                 alpha=0.02, history_window=18,
                                 horizons=[10, 20, 30]):
    # Reference = mean of last 18 prices
    ref = np.mean(history[:, -history_window:], axis=1)
    
    upper = (1 + alpha) * ref  # +2% band
    lower = (1 - alpha) * ref  # −2% band
    
    for h in horizons:
        # Classify true outcomes
        true_up = y_true[:, h-1] > upper
        true_dn = y_true[:, h-1] < lower
        # ... same for predictions, then compute accuracy

11. Statistical Significance Tests

Is the Improvement Real or Just Luck?

When Model A has MSE=14.0 and Model B has MSE=14.5, is A truly better? Or could random variation explain the difference? Statistical tests answer this.

Paired t-Test

Compares paired errors (same sample, different model). The null hypothesis: "there is no difference on average".

t = (mean of differences) / (SE of differences)
where SE = std(diffs) / √n 
t_stat, p_value = stats.ttest_rel(errors_a, errors_b)

If p-value < 0.05, we reject the null → the improvement is statistically significant at the 5% level.

Wilcoxon Signed-Rank Test

A non-parametric alternative (doesn't assume normal distribution). It ranks the absolute differences and compares the sum of positive vs. negative ranks.

stat, p_value = stats.wilcoxon(diff, alternative="two-sided")

Diebold-Mariano Test

Specifically designed for comparing forecast accuracy. Accounts for autocorrelation in forecast errors using a Newey-West variance estimator:

def diebold_mariano_test(errors_a, errors_b, h=1):
    d = errors_a - errors_b          # Loss differential
    d_mean = np.mean(d)
    d_var = np.var(d, ddof=1)
    
    # Newey-West: add autocorrelation correction
    for k in range(1, h):
        gamma_k = np.mean((d[k:] - d_mean) * (d[:−k] - d_mean))
        d_var += 2 * gamma_k
    
    dm_stat = d_mean / np.sqrt(d_var / n)
    p_value = 2 * (1 - stats.norm.cdf(abs(dm_stat)))

🎯 Why Three Tests?

Paired t-test: Simple, powerful if errors are roughly normal. Wilcoxon: Robust to non-normality and outliers. Diebold-Mariano: Handles autocorrelated forecast errors. If all three agree, we have strong evidence.

12. LLM Prompting Strategies

The Core Idea: Can an LLM Improve a Maths Model?

The Time Series Model (TSM) is great at learning patterns from numbers. But it can't read the news or understand that "EU tightens emissions targets" means prices will rise. The LLM can. The question is: how do we combine them?

Strategy 1: Direct Prompting (DP)

Give the LLM raw price history and ask it to forecast. No TSM involved.

# Simplified prompt (from src/llm/prompts.py)
"""
Historical Data: [65.20, 65.80, 66.10, ..., 68.40]
Current price: 68.40 EUR
20-day volatility: 1.85 EUR
5-day change: +3.20 EUR (+4.9%)

Task: Forecast the next 30 trading days.
Return JSON: {"yhat": [d1, d2, ..., d30]}
"""

Strategy 2: Chain-of-Thought (CoT)

"Think step by step" — forces the LLM to reason before answering:

"""
Think step by step:
1. Analyze the recent price trend and momentum
2. Consider the volatility regime
3. Identify support/resistance levels
4. Factor in carbon market seasonality
5. Generate your forecast

Your analysis: [LLM reasons here]
Based on your analysis: {"yhat": [...]}
"""

Strategy 3: TSM+LLM (Simple Refinement)

Give the LLM both the price history and the TSM forecast, and ask it to refine:

"""
Model Forecast: [68.50, 68.60, ..., 70.10]
Model predicts +2.5% over 30 days.

Task: Review and refine this forecast.
Is the trend direction reasonable? Is the magnitude realistic?
"""

Strategy 4: TSM+LLM-COT-SENT (Sentiment-Informed)

Adds daily news sentiment scores (−1 to +1) to the prompt:

"""
Recent prices: [65.20, ..., 68.40]
Sentiment history: [0.33, -0.67, 0.00, 1.00, 0.33, ...]
Model forecast: [68.50, 68.60, ..., 70.10]

Task: Adjust the forecast using sentiment signals.
Sentiment should nudge, not override, the model.
"""

Strategy 5: Delta-Based Refinement

Instead of outputting a full new forecast, the LLM outputs adjustments:

"""Task: Provide per-day additive adjustments (delta).
Keep each delta within ±0.50 EUR.
Return: {"delta": [+0.10, -0.05, ..., +0.30]}"""

# Final forecast = TSM forecast + delta
refined = tsm_forecast + delta

Strategy 6: Normalized Delta

Work in z-score space (standard deviations from the mean) so adjustments are scale-independent:

z = (price − mean) / std
norm_history = (history - mean) / std
norm_forecast = (tsm_forecast - mean) / std
# LLM adjusts in z-score space, then we convert back:
refined_prices = (norm_forecast + delta_z) * std + mean

💡 Temperature Parameter

The LLM's temperature controls randomness. At temperature=0, the model always picks the most likely token (deterministic). At temperature=1, it samples randomly. The repo uses temperature=0.1 for nearly-deterministic, reproducible outputs.

13. Two-Stage Reflect → Apply (CoT-RF)

The Key Innovation

Instead of asking the LLM to refine in one shot, we split the task into two stages:

Stage A: REFLECT ┌────────────────────────────────────────────────┐ │ Input: K teaching examples showing: │ │ • History → TSM forecast → True outcome │ │ • (optionally: sentiment history) │ │ │ │ Output: Plain-text CORRECTION RULES │ │ e.g. "Model overshoots after spikes by ~1.5€" │ │ e.g. "Negative sentiment leads to lag by 3d" │ └─────────────────────┬──────────────────────────┘ │ rules_text ▼ Stage B: APPLY ┌────────────────────────────────────────────────┐ │ Input: │ │ • Current history + TSM forecast │ │ • (optionally: current sentiment) │ │ • The rules from Stage A │ │ │ │ Output: Refined 30-day forecast (JSON) │ └────────────────────────────────────────────────┘

Stage A: Reflection (Learning from Mistakes)

# The reflect prompt shows K past examples:
"""
Example 1 (date=2024-03-15):
  History: [64.20, 64.50, ...]
  Model forecast: [65.00, 65.20, ..., 67.50]
  True outcome:   [64.80, 64.30, ..., 63.10]

Example 2 (date=2024-04-02):
  History: [63.10, 63.50, ...]
  ...

Task: Identify systematic deviations. Output correction rules.
Focus on: bias, lag, overshoot, mean reversion, horizon errors.

Rules: [LLM writes rules here]
"""

Stage B: Application

"""
Current price: 68.40 EUR
Recent prices: [65.20, ..., 68.40]
Model Forecast: [68.50, 68.60, ..., 70.10]

Correction Rules:
- Model tends to overshoot by ~1.2 EUR at h=30
- After positive momentum >3%, expect mean reversion by day 15
- Negative sentiment signals precede downturns by 2-3 days

Task: Apply the rules. Return refined forecast as JSON.
"""

Context Retention

A crucial optimisation: Stage B can retain the chat context from Stage A (using retain_context: true), so the LLM remembers the teaching examples and its own reasoning:

# Multi-message chat (like a conversation):
messages = [
    {"role": "user",    "content": stage_a_prompt},   # Examples
    {"role": "assistant", "content": rules_text},      # LLM's rules
    {"role": "user",    "content": stage_b_prompt},   # Apply now
]
response = client.chat.completions.create(messages=messages)

🎯 Why Two Stages?

By separating "learning rules" from "applying rules", we force the LLM to be explicit about what it learned. This is more reliable than hoping the LLM silently absorbed the lessons. It also lets us inspect what the LLM learned (the rules are readable text).

14. Sentiment Analysis Pipeline

From Raw News to a Daily Score

The pipeline converts thousands of noisy headlines into a clean daily sentiment signal:

1. Collect 2. Filter 3. Label 4. Aggregate GDELT/GKG → Relevance → LLM Vote → Daily Mean ~456k rows Score ≥ 2 YES/NO/UNK sent_score SimHash dedup 3 votes each per day Policy gate Majority wins

Step 1: Collection

Headlines fetched from GDELT using multiple queries (e.g., "EU ETS", "carbon trading", "emission allowances").

Step 2: Relevance Filtering

  • Heuristic EU ETS Score: Keywords scored 0–5, threshold at 2+
  • SimHash Dedup: Near-duplicate headlines removed (same story from multiple outlets)
  • Policy/Shipping Gate: Policy/shipping headlines dropped unless they mention ETS-specific terms

Step 3: LLM Labelling (Paper-Style)

Each headline is classified by the LLM as YES (price will rise), NO (fall), or UNKNOWN (neutral):

# Per headline, 3 independent votes (majority wins):
headline = "EU tightens 2030 emission caps as ETS reform advances"
votes = ["YES", "YES", "YES"]   # → unanimous YES → score = +1

headline = "Global shipping costs decline amid trade uncertainty"
votes = ["NO", "UNKNOWN", "NO"]  # → majority NO → score = -1

headline = "UK weather forecast shows mild winter ahead"
votes = ["UNKNOWN", "NO", "UNKNOWN"]  # → majority UNKNOWN → score = 0

Step 4: Daily Aggregation

Top 3 highest-scoring headlines per day → average their scores:

# Day with 3 headlines: scores = [+1, +1, -1]
daily_sentiment = mean([+1, +1, -1]) = +0.33

Dawid-Skene Aggregation (Advanced)

A probabilistic method from 1979 that estimates both the true label and each voter's reliability:

# Dawid-Skene iterates:
# E-step: estimate true labels given voter reliabilities
# M-step: estimate voter reliabilities given true labels
# Converges to posterior probabilities for each label
expected_score = P(YES)*(+1) + P(UNKNOWN)*(0) + P(NO)*(-1)

In practice, with a 4B model voting deterministically, all votes were nearly unanimous, making Dawid-Skene equivalent to majority vote.

⚠️ Key Finding from Experiments

Removing sentiment entirely (CoT-RF) actually outperformed sentiment-augmented methods (CoT-Sent-RF). The self-refinement signal was real (−13.78% MSE), but sentiment was too noisy to help further. This suggests the bottleneck is sentiment quality, not quantity.

15. Blending & Ramp Weighting

The Problem

The LLM improves long-horizon forecasts (Day 20–30) but harms short-horizon accuracy (Day 1–5). The TSM is already very precise at Day 1. How do we keep the best of both?

Solution: Horizon-Weighted Ramp Blending

ŷ_blend[h] = (1 − wₕ) · ŷ_TSM[h] + wₕ · ŷ_LLM[h]

Where the weights ramp up linearly from 0 to max_w:

wₕ = linspace(0, max_w, 30)

So w₁ = 0 (Day 1 is pure TSM) and w₃₀ = max_w (Day 30 gets most LLM influence).

Weight (wₕ) max_w ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ● │ ╱ │ ╱ │ ╱ │ ╱ │ ╱ │ ╱ │ ╱ 0 ─ ●─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─→ Horizon (h) 1 5 10 15 20 30 Pure TSM → Mostly LLM

Code Implementation

def _blend_forecast(self, base, refined):
    min_weight = 0.0    # w₁ = 0 (pure TSM at Day 1)
    max_weight = 0.75   # w₃₀ = 0.75 (75% LLM at Day 30)
    
    ramp = np.linspace(min_weight, max_weight, 30)
    # ramp = [0.0, 0.026, 0.052, ..., 0.75]
    
    blended = base * (1 - ramp) + refined * ramp
    return blended

Validation-Based Weight Selection

We don't hardcode max_w — we test 5 candidates on the validation set and pick the best:

16. Teaching Example Selection

Why Selection Matters

The Stage A reflection prompt receives K=5 "teaching examples" showing past TSM forecasts vs truth. Which 5 examples we choose dramatically affects what the LLM learns.

Selection Strategies

1. Most Recent

Simply pick the K most recent past windows. Problem: if recent history was calm, the examples all look similar → the LLM learns "do nothing".

2. High-Error (Where TSM Failed)

Select windows where the TSM had the largest errors:

# Rank past windows by TSM error, pick top K
errors = np.mean((forecast - truth)**2, axis=1)
top_k_indices = np.argsort(errors)[-K:]

Problem: without a lookback constraint, the same 5 extreme dates are chosen every time → same rules, no diversity.

3. Similarity-Based (Regime Matching)

Find past windows whose statistics resemble the current window:

# Features: mean, std, slope of recent prices
current_features = [mean(current), std(current), slope(current)]
past_features = [[mean(w), std(w), slope(w)] for w in past_windows]

# Euclidean distance → pick K closest
distances = np.linalg.norm(past_features - current_features, axis=1)
top_k = np.argsort(distances)[:K]

4. Lookback Constraint

Only consider examples within the last lookback_days=365 days. This prevents using ancient, possibly irrelevant data and ensures freshness.

🔑 Best Combo Found

Similarity + 365-day lookback produced the best results: −13.78% path MSE improvement. The similarity matching ensures relevant examples while the lookback ensures recency.

17. Quantile Regression & LASSO

Beyond the Mean: Predicting Uncertainty

Standard regression predicts the mean. Quantile regression predicts specific percentiles:

  • 10th percentile: "price will be above this 90% of the time"
  • 50th percentile: the median (another measure of centre)
  • 90th percentile: "price will be below this 90% of the time"

This gives us prediction intervals (confidence bands).

The Quantile Loss Function

ρ_q(u) = u · (q − 𝟙(u < 0))

For quantile q=0.9, errors where the prediction is too low (underestimate) are penalised 9× more than errors where it's too high. This pulls the prediction toward the 90th percentile.

LASSO (L1) Regularisation

LASSO adds an L1 penalty that forces some feature weights to exactly zero, performing automatic feature selection:

L = Σᵢ ρ_q(yᵢ − ŷᵢ) + α · Σⱼ |wⱼ|

Compare with Ridge (L2): Ridge shrinks weights but rarely zeroes them out. LASSO creates a sparse model.

Code Walkthrough

19. Results & Ablation Studies

The Ablation Approach

An ablation study tests "what happens if we remove or change one component?" This identifies which parts actually matter.

Key Findings (Full Test Set, n=359)

MethodMSE_pathChange vs TSM
TSM (baseline)14.52—
TSM + CoT-Sent-RF (early, damped)14.50−0.1%
TSM + CoT-RF (no sentiment, similarity+lookback)12.51−13.8%
TSM + CoT-Sent-RF (improved sentiment)13.89−4.3%

What Worked

  • Similarity-based example selection + lookback: The biggest win. Giving the LLM relevant, diverse teaching examples.
  • Context retention: Letting Stage B see Stage A's full conversation.
  • Ramp blending: Protecting short-horizon accuracy while gaining long-horizon improvement.
  • Removing damping: The original delta-bounded, conservative approach produced near-zero adjustments.

What Didn't Work

  • Multiple sentiment variations: EU-close alignment, confidence weighting, EWMA smoothing, domain weighting, richer features — all slightly worsened or were neutral.
  • 0–10 importance scoring: More complex sentiment labelling didn't improve on simple YES/NO/UNKNOWN.
  • Abnormal sentiment (z-score): +1.4% worse path MSE.
  • Dawid-Skene aggregation: Votes were too deterministic to benefit from probabilistic methods.

The Core Lesson

🎯 Self-Refinement > Sentiment

The LLM's ability to reflect on past TSM errors and learn correction rules was the primary source of improvement. Adding sentiment data was secondary and often counterproductive with a small model.
